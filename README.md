# Digital Payments for Persons with Disabilities — Phase 3 PoC evidence pack
SoI Innovation Projects AY2026-27 | Team ID P-2025-29-CD-061-AY26-27 (team Bytecloud) | working title in P1/P2: ScamShield-Access
Selected P2 concept: I02 Accessible Payment Truth Layer (provisional). Design lens: AI & Data (AD).

**All data are SYNTHETIC. No real payments, accounts, UPI, biometrics, user data or live users.**

## What the PoC tests (one risky assumption)
One verified payment record (WHO / HOW MUCH / WHAT / RISK / WHY) can be rendered as screen-reader text, visual card text,
simple-language text and a haptic pattern description that stay consistent, while a transparent rule-based risk level
meets pre-set recall and false-alert limits.

## Known limits
- Cases, labels and rules were drafted together with an AI assistant; the same authors wrote cases and rules, so results on set A
  (R01) are optimistic. Sets B and C were written after the rules they test were frozen.
- Team review of every label and a team re-run are PENDING; stakeholder / user review is PENDING.
- The haptic and audio outputs are text descriptions, not hardware or text-to-speech.
- 40 cases per run is a small teaching-scale sample; repeats of one case are not independent cases.
- Rule-based keywords may not generalise (see R02). Not a fraud-detection or accessibility claim.
